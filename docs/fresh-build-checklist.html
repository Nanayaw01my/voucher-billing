MikroTik fresh build

EUNISET LOVE · nothing on the router worth keeping · reset and build from scratch

Take with you: a laptop with Winbox, the file mikrotik-setup.rsc on it (or on a USB stick), an ethernet cable, and a phone to test the hotspot with.

Decide two passwords before you start and write them in Step 2. You will be asked for them mid-way and they are not recoverable afterwards.

Step 1 — the public IP test, BEFORE you reset

Do this first. It is the one thing a reset would make you redo, and it decides whether the online dashboard can ever reach this router.

/ip address print
/ip cloud set ddns-enabled=yes
/ip cloud print
WAN address (from /ip address print)
public-address (from /ip cloud print)
What you seeWhat it means
The two matchPublic IP. The online dashboard can reach the router.
They differCGNAT. Dashboard cannot dial in; run it on site or via a tunnel.
WAN starts 100.64.–100.127.CGNAT confirmed.

Write both down. Don't try to decide what it means on site.

Step 2 — choose your passwords now

Router admin password
API password (for the dashboard)

Edit these into mikrotik-setup.rsc before running it — search the file for CHANGE-ME. There are four.

Step 3 — reset

/system reset-configuration no-defaults=yes skip-backup=yes
The router reboots with no IP address at all. Reconnect with Winbox using the MAC address on the Neighbors tab — not an IP, there isn't one yet. Plug your laptop into ether2, not ether1.

Step 4 — load the configuration

Winbox → Files → drag mikrotik-setup.rsc in. Then:

/import file-name=mikrotik-setup.rsc

Watch the output. If a line fails, write down which one and carry on — most failures are a port name that differs on your model (ether5 on a 4-port router, for example). Check yours with /interface print.

Step 5 — check it came up

/ip address print
/ip hotspot print
/ip hotspot user profile print
/ip service print

You want: an address on ether1 from Starlink, 10.5.50.1 on the bridge, one hotspot server running, eight voucher profiles, and api enabled on 8728.

Step 6 — test with a phone

Connect to the access point's WiFi. A login page should appear. Sign in with:

username: TEST1234
password: TEST1234

Confirm you get real internet, then check the session is being counted:

/ip hotspot active print

You should see the phone listed with bytes climbing. Then remove the test voucher:

/ip hotspot user remove [find name=TEST1234]
If the login page never appears, the usual causes are: the access point is not plugged into ether2–ether5, or the AP is running its own DHCP server and should be in bridge/access-point mode instead.

Bring back

  • Step 1: both addresses
  • The two passwords you set
  • The router's LAN IP (should be 10.5.50.1)
  • Router model and RouterOS version (/system resource print)
  • Whether the phone test worked, and what the login page looked like
  • Any command that failed, and its exact message

If you get locked out

You cannot be permanently locked out of a MikroTik you are physically next to.

SituationWhat to do
No IP, cannot connectWinbox → Neighbors tab → connect by MAC address.
Forgot the password you just setReset again and start from Step 3. Nothing is lost.
Configuration is a messReset again. The script is repeatable — run it as many times as you need.
