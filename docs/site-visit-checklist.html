MikroTik site visit checklist

EUNISET LOVE · voucher system · work top to bottom · no internet needed on site

Before you start. Open Winbox, connect to the router, choose New Terminal (or SSH to the router's IP). Every command below runs on the router itself. To copy output, select it in the terminal and press Ctrl+C. Photograph the screen as a backup — a blurry photo beats a second trip.

Step 0 — write these down first

/system resource print
Router model
RouterOS version
Router LAN IP

Step 1 — the public IP test (the important one)

This decides whether the online dashboard can ever reach your router.

/ip address print
WAN address (the interface facing Starlink)
/ip cloud set ddns-enabled=yes
/ip cloud print
public-address
dns-name
What you seeWhat it means
The two addresses matchYou have a public IP. Everything can work from the online dashboard.
They differBehind CGNAT. Needs a tunnel, or run the system on site.
WAN starts 100.64.–100.127.CGNAT confirmed — that range is reserved for exactly this.

Write both numbers down either way. Don't try to judge it on site.

Step 2 — turn on the API

The API is already in the router. It only needs enabling.

/ip service print
/ip service enable api
/ip service enable api-ssl
/ip service print

Copy the whole table from the last command.

Step 3 — create a dedicated API user

Do not reuse your admin login. Choose a long password and write it here — it cannot be recovered later.

API password
/user group add name=voucher-api policy=api,read,write,test
/user add name=voucher-api group=voucher-api password=PUT-PASSWORD-HERE
/user print

Confirm voucher-api appears in the list.

Step 4 — capture the hotspot setup

The dashboard's packages must match these profile names exactly.

/ip hotspot print
/ip hotspot profile print
/ip hotspot user profile print
Profile names
 

Check whether accounting is on — without it, usage figures are impossible:

/ip hotspot user profile print detail

Look for accounting= on each profile. Note any that say no.

Step 5 — export your vouchers (bring this file back)

/ip hotspot user print count-only
Voucher count
/ip hotspot user export file=vouchers
This creates vouchers.rsc on the router. Get it off via Winbox → Files → find vouchers.rsc → drag it to your desktop (or right-click → Download). Copy it to a USB stick too.

This file is the point of the trip — it is your entire voucher stock, and the system imports it directly.

If export is unavailable on your version, use this instead and take the file the same way:

/ip hotspot user print detail file=vouchers

Step 6 — active sessions (optional)

/ip hotspot active print

Shows whether accounting is producing real numbers.

Step 7 — only if Step 1 showed a PUBLIC IP

/ip firewall filter print

Copy the output. Do not open any port yet — we will add a rule restricted to one source address rather than exposing the API to the whole internet.

Bring back

  • vouchers.rsc — the export file (most important)
  • Step 1: both addresses
  • Step 2: the /ip service print table
  • Step 3: the API password you chose
  • Step 4: profile names, and which have accounting off
  • Step 5: voucher count
  • Step 6: active sessions output
  • Router model and RouterOS version

If something goes wrong

ProblemWhat to do
A command errorsWrite the exact message down and move on. Nothing here is destructive; a failed command changes nothing.
/ip cloud not availableOlder RouterOS. Skip it — the WAN address plus the 100.64–100.127 rule still answers the question.
Worried about lockoutAdding a user and enabling a service cannot lock you out. Your own login is unchanged.

To undo everything:

/ip service disable api
/ip service disable api-ssl
/user remove voucher-api
/user group remove voucher-api
Nothing in this checklist touches your hotspot, your existing vouchers, or any connected customer. Customers stay online throughout.
